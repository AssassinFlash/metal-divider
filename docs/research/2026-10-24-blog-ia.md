## 结论速览

1. 废弃旧站三分类(design-guide / knowledge / technical),改为 **5 个分类**,每个分类即一个 topic cluster,分类档案页兼任 cluster hub。
2. URL 基座用 **`/blog/`**(不用 `/resources/`),文章扁平 `/blog/<slug>/`,分类档案 `/blog/<category>/`;Polylang 子目录式各语种独立分类 slug。
3. 互链按 hub-and-spoke:文章 → 产品族页 + 图案系列 + 具体图案页;图案页/产品族页经 ACF 关系字段反向回链,给 146 个图案页持续输权。
4. 首批 10 篇以**采购指南 + 对比文**为主——这两类是实测 AI 引用率第一、第二的内容形态。
5. 与 Marketing-Vault 三处实质冲突(URL 平台基座、llms.txt 预期、FAQ rich results 现状)与一处事实基线更新(图案资产),逐条见 §6。

## 1. 设计依据

- **Topic cluster 规则**(HubSpot 原始方法论):一个 hub,cluster 页各覆盖一个子题;每个 cluster 页链向 pillar,pillar 链向所有重要 cluster 页(在引入子题的段落处),cluster 之间仅在"对读者有意义"时选择性互链;hub 页置于站点层级高处。
- **AI 引用特征**(Google 官方 + Princeton GEO 论文):AI Overviews/AI Mode 无额外收录要求,"query fan-out" 会引用更广的链接集;引用偏好自包含段落、精确数字、明确来源引用的文本(引用来源/引号/统计三类手法带来 30-40% 相对可见度提升),关键词堆砌无效。
- **同类站实证**(3 家,§8 有完整 URL):
  - **Banker Wire**(编织金属网):教育内容长在 `/resources/materials/` 材料集群(8 篇合金指南),图案产品页 ↔ 资源页双向互链(图案页的 "Living Finish" 注释直接链 `/resources/care-and-maintenance/#living-finishes`),材料页尾部链项目故事 + 样品申请。教育 → 证明 → 样品的闭环。
  - **Arktura**(穿孔/声学板):`/resources/` 教育枢纽 + 文章直链产品的密度全场最高——"12 个穿孔吊顶案例"文章每个案例都附 "Featuring: [产品名](产品 URL)";另有 NRC 解释长文充当 pillar 并带注册下载。
  - **Hendrick**(穿孔金属,产品最接近):反面教材为主——`/blog/` 混入人事/收购新闻淹没技术文章,最好的一篇对比文居然 `robots: noindex`。
  - 共同模式:教育内容贴着产品目录长(不进新闻博客筒仓);材料/how-it's-made 集群是骨架;文章是产品发现面(反复链具体产品页);交互式规格工具(开孔率计算器等)是引链资产。反面:公司新闻稀释教育库;无叙事的图片倾倒页。
- **Marketing-Vault**:site-architecture §7 的 hub-and-spoke、ai-seo-strategy 的引用内容类型排名与段落级可引用性、keyword-master-list 与 content-gap-priorities 的选题底稿、copywriting 的文风纪律、2026-07-10 事实核查确立的内容红线。

## 3. URL 方案(Polylang 子目录式兼容)

### 3.1 基座:`/blog/` 而非 `/resources/`

- 本期内容全部是编辑性文章,没有下载物/规格书库——`/resources/` 会承诺兑现不了的东西(Banker Wire、Arktura 的 `/resources/` 都以下载中心为实体)。未来若有 CAD/规格书下载,再加独立 `/resources/` 区,互不干扰,不需要 URL 迁移。
- `/blog/` 是 WordPress 原生形态(固定链接结构 `/blog/%postname%/`),Hendrick 同构;对排名而言目录名本身权重可忽略,结构才是关键。
- 与 vault 导航不冲突:vault 的 Resources 是**导航伞**(Blog/FAQ/Downloads),不是 URL 目录。新站导航仍可挂 Resources 伞,URL 保持 `/blog/`。

### 3.2 结构

```
(EN 基座,假设默认语言隐藏前缀——最终由 #3 选型票定)
/blog/                          博客首页(全部文章流)
/blog/buying-guides/            分类档案 = cluster hub(300-500 词导言 + 全部文章)
/blog/materials-finishes/
/blog/manufacturing/
/blog/applications/
/blog/comparisons/
/blog/<article-slug>/           文章,扁平,不进分类路径

/es/blog/                       其余 8 语种 = 语言前缀 + 同构
/es/blog/guias-de-compra/       分类 slug 各语言独立(Polylang 分类按语言建 term)
/es/blog/<translated-slug>/
```

- **文章 URL 扁平、分类不进路径**:换分类不动 URL(避免 301 债);Polylang 下少一层路径组合;Hendrick 同构(` /blog/flatness-tolerances/` vs `/blog/architectural/`)。
- 面包屑仍展示分类:Home > Blog > Category > Article(SEOPress Pro 输出,栈内已有)。
- **Polylang 事实依据**:目录式语言模式为原生选项;分类/标签按语言各建互链 term、slug 可各语言不同;翻译页自动出 hreflang,x-default 仅首页(Pro)。分类导言与文章正文一样走翻译管线。
- **旧站三分类处理**:旧 `/blogs/{design-guide,knowledge,technical}/...` 按文章级 301 到 `/blog/<slug>/`,映射表归 #4(SEO 底账与 301 规则)票;本票只定原则——分类页权重低(旧站仅 5 篇测试文,无真实流量包袱),按主题就近映射即可。
- **sitemap**:WP 原生 sitemap + Polylang 按语言出条目;分类档案页纳入。llms.txt(§6 第 8 条)同步改为指向新 `/blog/` 结构。

## 4. 互链模型(给 146 图案页与 8 产品族页输权)

四层结构,规则遵循 HubSpot cluster 规则 + Google 内链通用指引(每个重要页面至少有一条站内入链;锚文本描述性、不堆砌):

```
分类档案页(hub)
  ├── 链向本类全部文章(hub→spoke 全量)
  ├── 链向对应产品族页(如 manufacturing ↔ 激光切割板/穿孔板/拉伸金属板族页)
  └── 导言段落自然带出 1-2 个图案系列档案

文章(spoke)
  ├── 每篇至少链 1 个产品族页(对应主题)
  ├── 每篇链 2-4 个图案页或图案系列档案(图案图鉴型每例 1-2 个具体图案页)
  ├── 同类文章选择性互链(仅当对读者有意义;对比文 ↔ 材质文天然互补)
  └── CTA → 图案清单(pattern list)/询盘——内容终点始终回到唯一转化链

反向(数据驱动,不逐页手改)
  ├── 图案页(Woo 产品)"Design guides" 区块:按系列↔分类映射自动 + ACF 关系字段手动精选 2-3 篇
  └── 产品族页 "Deep dive" 区块:链 3-5 篇最相关文章
```

- **图案页输权路径**:146 个图案页的主要入链来自(1)图案系列档案、(2)产品族页、(3)图案图鉴型文章的逐例链接。第 (3) 条是唯一可持续增长的来源——每发一篇图鉴文,就有 10-20 个图案页新增一条带语义锚文本的入链(Arktura 逐例链接模式的直接移植)。
- **锚文本规范**(vault §7.3 延伸):文章链图案页用 "laser-cut geometric pattern [系列/图案名]" 这类描述性锚文本,禁 "click here";图案页回链文章用 "how open area affects privacy" 这类问题式锚文本。
- **映射关系随内容模型落库**:系列↔分类、产品族↔分类的对应关系建为配置(ACF 字段或代码常量),系列档案 URL 形态由 #6(产品数据模型)票定,本票只锁逻辑关系。

## 7. 内容生产与红线落点(喂 #11 原型票)

- **工作流**:业主写 Markdown → yansir-md 粘贴 → LiveCanvas 动态模板。原型票需承载:文章模板(pillar/cluster/图鉴三型)、分类档案页模板(导言区 + 文章流 + 产品族页链接区)、文内 FAQ 区块样式。
- **段落级可引用性**(ai-seo-strategy §6.5 直接沿用):每段独立回答一个问题;开头即结论;精确数字替代形容词;H2/H3 用疑问句。
- **内容红线**(继承 vault 处置口径,文章一律适用):不声明认证(ISO/SGS 等);盐雾等测试仅"可安排";最大幅面/厚度"按图纸确认";不写 free sample;不引用项目案例、出口国家数、成立年份;工厂规模类数字未经业主确认不入文。Vault 中已标注 [NOTE TO METALDIVIDER] 的 MOQ/交期/保修字段,以业主确认值替换后才可入文。
- **Schema**:每篇 BlogPosting + BreadcrumbList(SEOPress Pro);嵌入视频时 VideoObject + transcript;FAQ 区块可见文本为主。
