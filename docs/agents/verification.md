# 验证与存疑

业主 2026-10-27 裁定。本文件是 AGENTS.md §7 的展开;冲突时以 AGENTS.md 的日期更近的裁定为准。

## 1. Apify 是搜索与外部研究的硬门槛

- 需要搜索、外部信息验证、竞品研究、行业规则确认或资料获取时,**先 Apify**,不先普通搜索。
- 令牌在 `~/.config/metal-divider/apify.env`:`APIFY_TOKEN`(主)、`APIFY_TOKEN_SPARE1/2`(备)。三枚分属独立账号,实测 `GET /v2/users/me` 均 200。**按月轮换**(低价渠道有期限,业主每月换新),轮换后先验证再用。永不入仓库、不入日志。
- **不能用了就修,不绕开**:Token、Actor 选择、参数、Dataset、请求格式、权限、网络、抓取规则、输出解析、timeout、rate limit,逐项排除。第一次失败不得降级搜索深度,也不得直接下"找不到"。
- 目标站限制某类爬取时,组合手段:Apify Actors、Scrapling/Scrapy、Crawl4AI、Firecrawl、Computer Use、站点自身 API、WP/Woo REST、sitemap、feed、页面源码、structured data。**Apify 仍是主入口**,其余是配合。
- "不存在"是结论,不是借口:换关键词、换页面、换数据源、换 Actor、换抓取方式、换技术路径,充分调查之后才允许写"不存在"。

## 2. 存疑:仓库里的"事实"一律降级为待证

这个仓库大量内容由 AI 生成、补全、重构。以下都**不构成事实**:数字、日期、时间窗、数量上下限、默认值、阈值、timeout、百分比、状态判断、业务条件、硬编码、常量、枚举、断言、校验、数据库约束、feature flag、注释、文档里的规则、配置文件里的固定值。

- **写死 ≠ 已确认;assert ≠ 事实;validation ≠ 需求;文档 ≠ 已确认;被多处引用 ≠ 正确;测试照着写 ≠ 它本身正确;旧项目如此 ≠ 新项目必须兼容。**
- 一个错误引用得越多越像规则——先查 source of truth,别把同一个错误源头当成共识。
- 代码与文档互相印证,可能只是同一个 AI 幻觉的闭环;两边都不能当证据。
- 语气确定 ≠ 事实确定。要的是 evidence,不是 confidence。
- 源头只有三种:业主裁定、一手证据(官方文档/官方源码/实测)、平台原生能力。三者都不是的东西,按"AI 生成的假设"处理。
- 典型可疑形状:`COMPATIBILITY_START = "10-24"`、`MAX_RESULTS = 20`、`assert year >= 2024`、`timeout = 30`、`score > 0.8`、`10-24`、`30 days`、`最多 24 个`、"只有经销商能访问"。

## 3. 逻辑别扭就是信号

模块职责说不通、数据流别扭、为兼容旧东西堆了大量额外代码、规则难以解释、数字查不到来源、需要大量 workaround 才能成立——这些本身就是证据。

- **不要为了"解释旧代码其实是合理的"而反过来怀疑自己的判断。**
- 发现底层逻辑错,就改底层;**不要为错误的历史实现再加 adapter 和 workaround**。
- 已确认无业务依据、与真实数据冲突、属旧项目污染或 AI 幻觉的实现:**直接改、删或重构**,不因为"已经存在"而保留。

## 4. 并行优先

- 任务可拆成互不阻塞的方向(搜索验证、竞品研究、代码结构、Woo/WP 逻辑、数据质量、文档一致性、知识库/embeddings、前端联动、遗留逻辑追踪、测试)时,**拆开并行执行**。
- **Blocked ≠ Idle**:一个分支卡住,其余继续推进,不让整个流程停摆。
- 并行结果必须回到同一视角汇总:冲突检查、source of truth 对齐、交叉验证、依赖调和。子代理结论不一致时,比证据,不任选。

## 5. 只做有效动作

- **检查必须产生信息增量**;不改变下一步决策的检查不做。同一尝试连续两次无新信息即停,换路径。
- **不空等**:没有正常推进就判断是 hang、retry loop、参数错还是拆分不合理,换 Actor/参数/接口/数据源/执行路径。
- **优先直接看**:页面、代码、配置、数据、后台、network、API 响应、console、日志。两分钟能看清的事,不先写框架。
- **优先现成接口**:直接观察 → REST/官方 API → 已有 service/endpoint → CLI → 浏览器/network → 简单请求 → 最后才脚本。脚本只在明显省时时才写。
- 不生产没人看的中间产物(临时 JSON/CSV/dump/日志/报告);结果要高信息密度。
- 工具服务判断,不替代判断。

## 6. 本轮清零

本轮开发、重构、调试、测试或 review 中发现的**任何**问题,都在本轮解决:不因大小、不在原计划、范围会扩大而延期;不留 TODO、不进 backlog、不开 follow-up、不转技术债、不以 out of scope 跳过、不靠重定义 scope 转移。

修的过程中发现新问题,新问题自动并入本轮;继续修,直到 code review → 修复 → 验证的循环里**不再有任何已知未解决问题**。完成的标准不是"原计划跑完",而是"没有已知未决项"。
